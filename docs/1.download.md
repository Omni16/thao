# FujiOS --- `1.download.md`

> Tài liệu thiết kế **Download Layer** cho hệ thống build FujiOS.
>
> Mục tiêu: nhận một URL/file/link từ người dùng, xác định loại nguồn,
> chọn downloader phù hợp, tải ROM ổn định, resume được, kiểm tra
> integrity và tạo metadata để các bước
> `detect → extract → patch → repack` sử dụng.
>
> **Phạm vi:** MIUI / HyperOS / Android OTA / Fastboot ROM / ZIP /
> payload OTA / mirror / CDN / cloud storage / GitHub-GitLab / FTP-SFTP
> / torrent / Metalink / URL động.
>
> **Nguyên tắc:** FujiOS không nên phụ thuộc vào duy nhất một
> downloader. Downloader phải là một **backend layer** có resolver +
> policy + verification ở phía trên.

------------------------------------------------------------------------

## 1. Mục tiêu của Download Layer

Pipeline chuẩn:

``` text
User
 │
 ├── URL
 ├── local file
 ├── mirror URL
 ├── torrent / magnet
 └── provider request
        │
        ▼
┌───────────────────────────────┐
│ Input / URL Resolver          │
│ - detect provider             │
│ - normalize URL               │
│ - resolve redirect/CDN        │
│ - auth/cookie/header          │
└───────────────┬───────────────┘
                ▼
┌───────────────────────────────┐
│ Download Manager              │
│ - backend selection           │
│ - retry                       │
│ - resume                      │
│ - parallel connections        │
│ - rate limit                  │
│ - disk-space check            │
└───────────────┬───────────────┘
                ▼
┌───────────────────────────────┐
│ Downloader Backend            │
│ aria2 / curl / wget / ...     │
└───────────────┬───────────────┘
                ▼
┌───────────────────────────────┐
│ Verification                  │
│ size / SHA256 / signature     │
└───────────────┬───────────────┘
                ▼
       `download.json`
                │
                ▼
       ROM Analyzer / Extractor
```

# 3. Direct HTTP/HTTPS --- phương án chính

Đây là trường hợp quan trọng nhất đối với ROM.

Ví dụ:

``` text
https://cdn.example.com/miui_xxx.zip
https://bigota.d.miui.com/...
https://dl.google.com/...
https://mirror.example.com/...
```

## 3.1 `aria2c` --- backend chính được khuyến nghị

`aria2` là downloader CLI đa giao thức, hỗ trợ HTTP(S), FTP, SFTP,
BitTorrent và Metalink; có segmented/multi-connection download, checksum
Metalink và JSON-RPC/XML-RPC. Đây là ứng viên rất phù hợp làm backend
mặc định cho FujiOS. citeturn0search7turn0search8

### Điểm mạnh

-   HTTP/HTTPS
-   FTP
-   SFTP
-   BitTorrent
-   Metalink
-   nhiều connection
-   resume
-   retry
-   checksum
-   proxy
-   cookie
-   custom header
-   authentication
-   RPC
-   download từ nhiều source
-   giới hạn tốc độ
-   IPv6
-   có thể chạy daemon

### Ví dụ

``` bash
aria2c \
  -x 16 \
  -s 16 \
  -k 1M \
  -c \
  --max-tries=10 \
  --retry-wait=5 \
  -d downloads \
  -o rom.zip \
  "https://example.com/rom.zip"
```

Trong đó:

``` text
-x 16       = tối đa 16 connection/server
-s 16       = chia file thành 16 segment
-k 1M       = kích thước piece
-c           = resume
```

### Có header

``` bash
aria2c \
  --header="User-Agent: Mozilla/5.0" \
  --header="Authorization: Bearer TOKEN" \
  -c \
  "https://example.com/rom.zip"
```

### Cookie

``` bash
aria2c \
  --load-cookies=cookies.txt \
  -c \
  "https://example.com/rom.zip"
```

### RPC

FujiOS có thể chạy một `aria2c` daemon và điều khiển bằng JSON-RPC.

``` bash
aria2c \
  --enable-rpc=true \
  --rpc-listen-all=false \
  --rpc-secret=FUJI_SECRET
```

**Thiết kế khuyến nghị:**

``` text
Fuji Downloader
      │
      ▼
aria2 RPC
      │
      ├── addUri
      ├── pause
      ├── resume
      ├── remove
      └── status
```

Điều này hữu ích nếu Telegram bot gửi nhiều job build cùng lúc.

# 4. `curl` --- HTTP fallback / API client

`curl` rất phù hợp khi FujiOS cần:

-   redirect
-   header
-   cookie
-   API
-   POST
-   authentication
-   signed URL
-   kiểm tra HTTP response
-   download đơn giản

Ví dụ:

``` bash
curl -L \
  --retry 10 \
  --retry-all-errors \
  -C - \
  -o rom.zip \
  "https://example.com/rom.zip"
```

Header:

``` bash
curl -L \
  -H "User-Agent: Mozilla/5.0" \
  -H "Authorization: Bearer TOKEN" \
  -o rom.zip \
  "https://example.com/rom.zip"
```

Cookie:

``` bash
curl -L \
  -b cookies.txt \
  -c cookies.txt \
  -o rom.zip \
  "https://example.com/rom.zip"
```

### Khi FujiOS nên dùng curl

``` text
API request
     ↓
resolver
     ↓
curl
     ↓
direct CDN URL
     ↓
aria2
```

Không nhất thiết phải dùng aria2 cho mọi request.

# 5. `wget` --- fallback tương thích

`wget` là lựa chọn rất phổ biến trên Linux và phù hợp làm fallback.

``` bash

  --continue \
  --tries=10 \
  --timeout=60 \
  -O rom.zip \
  "https://example.com/rom.zip"
```

Có header:

``` bash
wget \
  --header="User-Agent: Mozilla/5.0" \
  -c \
  -O rom.zip \
  "https://example.com/rom.zip"
```

### Vị trí trong FujiOS

``` text
aria2
  ↓ fail
curl
  ↓ fail
wget
```

# 11. HTTP Range Requests

Đây là kỹ thuật rất quan trọng.

Server có thể cho phép:

``` http
Range: bytes=0-1048575
```

Downloader chỉ lấy một phần file.

Điều này đặc biệt hữu ích với ROM nhiều GB.

Ví dụ:

``` text
ROM.zip
│
├── byte 0 → 1 MB
├── byte 1 MB → 2 MB
├── byte 2 MB → 3 MB
└── ...
```

### FujiOS nên kiểm tra

``` text
HEAD
 ↓
Accept-Ranges
Content-Length
Content-Type
ETag
Last-Modified
Content-Disposition
```

Nếu server hỗ trợ Range:

``` text
parallel download = YES
```

Nếu không:

``` text
single stream
```

# 14. Differential / Incremental OTA

OTA có thể là:

``` text
FULL OTA
```

hoặc:

``` text
INCREMENTAL OTA
```

Incremental có thể cần base images.

``` text
old ROM
   +
incremental payload
   ↓
new images
```

`payload-dumper-go` hỗ trợ extraction cho differential OTA với base
images. citeturn0search0turn0search5

FujiOS phải nhận diện:

``` json
{
  "ota_type": "incremental",
  "requires_base": true
}
```

Không nên coi mọi `payload.bin` là full OTA.

# 71. Kết luận

Đối với FujiOS, **không nên chọn một tool duy nhất**.

Bộ lõi nên là:

``` text
aria2c
   +
curl
   +
wget
   +
Python resolver
   +
provider adapters
   +
SHA256 verification
   +
cache
```

Trong đó:

``` text
aria2c
```

là downloader backend chính.

``` text
curl
```

là API/resolver/fallback.

``` text
wget
```

là fallback tương thích.

``` text
rclone
```

là cloud/storage backend.

``` text
Playwright
```

chỉ dùng khi cần giải quyết URL động.

``` text
provider resolver
```

là phần quyết định FujiOS có thể xử lý tốt MiFirm/Xiaomi/HyperOS hay
không.

Đặc biệt, **download và extract phải là hai layer khác nhau**:

``` text
DOWNLOAD
    ↓
verify
    ↓
ROM FILE
    ↓
ANALYZE
    ↓
EXTRACT
```

Không nên trộn chúng thành một script Bash duy nhất.

Payload extraction nên để layer kế tiếp. `payload-dumper-go` hiện hỗ trợ
local file, HTTP URL, ZIP và differential OTA, nên nó có thể trở thành
backend cho **Extract Layer**, thay vì nằm trong Download Layer.
