# FujiOS --- `2.nhan-dien-rom.md`

> **ROM Recognition / ROM Identification Layer**
>
> Mục tiêu của module này là nhận một file ROM đã tải xuống hoặc một URL
> đã được Download Layer xử lý, sau đó **tự động xác định ROM là gì,
> dành cho thiết bị nào, phiên bản nào, region nào, Android nào, loại
> package nào, có `payload.bin` / `super.img` hay không, các partition
> nào tồn tại và cần extractor nào**.
>
> Module này **chưa sửa ROM** và **chưa build ROM**. Nó chỉ phân tích và
> tạo metadata chính xác để các layer tiếp theo sử dụng.

------------------------------------------------------------------------

# 1. Vị trí của ROM Recognition trong FujiOS

Pipeline tổng thể:

``` text
                 USER
                   │
                   ▼
          ┌─────────────────┐
          │ 1. DOWNLOAD     │
          │ URL / file      │
          │ provider / CDN  │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 2. ROM DETECTOR │
          │ nhận diện ROM   │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 3. EXTRACT      │
          │ payload/super   │
          │ boot/vendor...  │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 4. ANALYZE      │
          │ partitions/prop │
          │ AVB/FS/metadata │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 5. PATCH        │
          │ FujiOS changes  │
          └────────┬────────┘
                   │
                   ▼
          ┌─────────────────┐
          │ 6. REPACK       │
          │ img/super/zip   │
          └────────┬────────┘
                   │
                   ▼
             FujiOS ROM
```

**Điểm quan trọng:**

``` text
Download ≠ Recognition ≠ Extraction
```

Ba layer phải tách riêng.

# 3. Không được nhận diện chỉ bằng filename

Ví dụ:

``` text
miui_DEVICEGlobal_V14.0.5.0.zip
```

Tên file có thể giúp nhận diện nhưng **không được coi là nguồn sự thật
duy nhất**.

Có thể xảy ra:

``` text
filename sai
filename bị rename
mirror đổi tên
user tự đổi tên
ROM repack
ROM bị cắt/đổi extension
```

FujiOS phải sử dụng nhiều tầng bằng chứng:

``` text
1. filename
2. URL
3. archive structure
4. archive metadata
5. payload metadata
6. partition metadata
7. build.prop
8. system properties
9. vendor properties
10. product properties
11. vbmeta
12. boot image
13. super metadata
14. filesystem
15. package scripts
```

Sau đó mới kết luận.
